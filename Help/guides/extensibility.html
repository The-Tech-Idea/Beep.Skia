Extensibility & Plugins

Plugin system, AssemblyHandler integration, and dynamic component loading

Beep.Skia extensibility architecture enables third-party developers to package diagram families, custom components, and UI controls as standalone plugins. Plugins can be distributed as NuGet packages, loaded dynamically at runtime, and discovered automatically by the palette and serialization systems.

SkiaComponentRegistry

SkiaComponentRegistry (661 lines) is the central registry for discovering, cataloging, and loading all SkiaComponent subclasses across assemblies. It serves as the single source of truth for component type resolution, used by the palette, serialization, and plugin loading systems.

ResponsibilityDescriptionLines
Assembly ScanningScans loaded assemblies for types deriving from SkiaComponent~120

Type ResolutionResolves full type names from serialized diagrams back to CLR types~100

Registry Architecture

The registry maintains three internal dictionaries optimized for different lookup patterns:

IndexKeyValueUsed By
_typeMapFully-qualified type nameTypeSerialization, deserialization
_componentMapCategory + DisplayNameTypePalette, toolbox, drag-and-drop
_metadataMapTypeComponentMetadataProperty inspection, tooltips, icons

Registry Usage

var registry = SkiaComponentRegistry.Instance;

// Register a component type manually
registry.Register(typeof(ValveNode), "Piping & Instrumentation", "Valve");

// Register with metadata
registry.Register(new ComponentMetadata
{
    ComponentType = typeof(PumpNode),
    Category = "Piping & Instrumentation",
    DisplayName = "Pump",
    IconGlyph = "◯",
    Tooltip = "Centrifugal or positive-displacement pump",
    DefaultWidth = 70f,
    DefaultHeight = 70f,
    Author = "Your Company",
    Version = "1.0.0"
});

// Resolve a type from serialized form
Type valveType = registry.ResolveType(
    "Beep.Skia.Chart.PnID.Nodes.ValveNode");
var component = registry.CreateInstance(valveType);

// Query all registered components in a category
var pnidComponents = registry.GetComponentsInCategory(
    "Piping & Instrumentation");
foreach (var meta in pnidComponents)
    Console.WriteLine($"- {meta.DisplayName} ({meta.ComponentType.Name})");

AssemblyHandler Integration

The AssemblyHandler bridges Beep.Skia with the broader BeepDM plugin infrastructure. It loads external assemblies, discovers [AddinAttribute]-marked components, and feeds them into the SkiaComponentRegistry.

Plugin Loading Phases

  1. Load Phase: AssemblyHandler.LoadAllAssembly() scans plugin directories and NuGet package folders for assemblies referencing Beep.Skia.
  2. Scan Phase: Each loaded assembly is scanned for types decorated with [AddinAttribute] and types that inherit from SkiaComponent.
  3. Register Phase: Discovered types are registered with SkiaComponentRegistry, making them available for palette integration and serialization.
  4. Instantiate Phase: When a user drags a component from the palette or opens a serialized diagram, the registry resolves the type and creates an instance.
  5. Unload Phase: (Optional) Assemblies can be unloaded via AssemblyLoadContext when plugins are removed or updated.

AssemblyHandler Configuration

var handler = new AssemblyHandler(new AssemblyHandlerOptions
{
    PluginDirectories = new[]
    {
        Path.Combine(AppDomain.CurrentDomain.BaseDirectory, "Plugins"),
        Path.Combine(Environment.GetFolderPath(
            Environment.SpecialFolder.LocalApplicationData),
            "BeepDM", "SkiaPlugins")
    },
    NuGetSources = new[]
    {
        "https://api.nuget.org/v3/index.json",
        "https://nuget.your-company.com/v3/index.json"
    },
    AutoLoad = true,
    WatchForChanges = true,
    RecursiveScan = true
});

handler.LoadAllAssembly();

var registry = SkiaComponentRegistry.Instance;
Console.WriteLine($"Loaded {registry.ComponentCount} component types");

Automatic Assembly Resolution

When a diagram references a component type from an assembly that is not loaded, the AssemblyHandler can attempt automatic resolution by searching NuGet sources for a package matching the assembly name. This enables sharing diagrams containing custom components without manually installing the plugin.

[AddinAttribute]

The [AddinAttribute] is the primary mechanism for marking your plugin assembly for automatic discovery. Applied at the assembly level, it provides metadata that the AssemblyHandler and SkiaComponentRegistry use to catalog and display your components.

Assembly-Level Addin Declaration

using Beep.Skia;

[assembly: Addin(
    Name = "Beep.Skia.Chart.PnID",
    DisplayName = "Piping & Instrumentation Diagrams",
    Description = "Process engineering diagram family with ISA S5.1 symbols",
    Version = "2.1.0",
    Category = "Engineering",
    Author = "Process Engineering Team",
    Company = "Acme Corp",
    TargetFramework = "net8.0;net9.0",
    Dependencies = new[] { "Beep.Skia >= 3.119.0" },
    Tags = new[] { "piping", "instrumentation", "P&ID", "ISA" }
)]

AddinAttribute Properties

PropertyRequiredDescription
NameYesUnique identifier. Convention: Beep.Skia.Chart.<Family>
DisplayNameNoHuman-readable name shown in the plugin manager
DescriptionNoShort paragraph describing the plugin purpose
VersionNoSemVer version string for compatibility checks
CategoryYesPalette category where components appear
AuthorNoIndividual or team name
CompanyNoOrganization name
TargetFrameworkNoSupported TFMs (e.g., net8.0;net9.0)
DependenciesNoArray of required packages with version constraints
TagsNoKeywords for search and filtering

Type-Level Addin

You can also apply [Addin] at the individual component class level to register specific types with custom metadata without requiring an assembly-level attribute. This is useful for libraries that contain multiple component families in a single assembly.

Plugin Lifecycle

Each plugin assembly goes through a defined lifecycle from discovery to potential unload:

Lifecycle Stages

StageMethod / TriggerWhat Happens
1. DiscoveryFile system scan or NuGet queryAssemblyHandler finds DLLs in plugin directories or searches NuGet feeds for packages with matching tags
2. LoadAssemblyLoadContext.LoadFromAssemblyPath()Assembly is loaded into an isolated AssemblyLoadContext. Dependencies are resolved. The [Addin] attribute is read.
3. ScanReflection over exported typesAll public types inheriting from SkiaComponent are discovered. Each type's metadata (name, category, default size) is extracted.
4. RegisterSkiaComponentRegistry.Register()Each discovered type is added to the registry's type map, component map, and metadata map.
5. InstantiateActivator.CreateInstance()Component instances are created on demand (palette drag or deserialization). Constructor and Initialize() run.
6. UnloadAssemblyLoadContext.Unload()All types from the assembly are removed from the registry. Existing instances are disposed. Assembly is released from memory.

Plugin Lifecycle Events

public class PluginLifecycleLogger
{
    public void Subscribe(SkiaComponentRegistry registry)
    {
        registry.PluginLoaded += (sender, args) =>
        {
            Console.WriteLine($"Plugin loaded: {args.AddinName} v{args.Version}");
            Console.WriteLine($"  Types registered: {args.ComponentCount}");
        };

        registry.PluginUnloaded += (sender, args) =>
        {
            Console.WriteLine($"Plugin unloaded: {args.AddinName}");
            Console.WriteLine($"  Active instances: {args.ActiveInstanceCount}");
        };

        registry.TypeRegistrationFailed += (sender, args) =>
        {
            Console.WriteLine($"Failed to register {args.TypeName}: {args.Error}");
        };
    }
}

Unload Safety

Unloading a plugin assembly while components are actively rendered on the canvas will cause ObjectDisposedException on the next frame. Always remove all components of the unloaded type from the DrawingManager before unloading the assembly. The registry provides GetActiveInstances(Type) to find all live component instances before unloading.

ComponentPalette

The ComponentPalette is the visual toolbox that displays available component types grouped by category. It discovers available components through the SkiaComponentRegistry and presents them as draggable items.

Palette Discovery Process

  1. On initialization, the palette queries SkiaComponentRegistry.GetAllCategories() to build the category list.
  2. For each category, it queries SkiaComponentRegistry.GetComponentsInCategory() to populate draggable items.
  3. Each item displays its IconGlyph, DisplayName, and Tooltip from the registry metadata.
  4. On drag, the palette creates a preview bitmap using the component's DrawContent() at DefaultWidth x DefaultHeight.
  5. On drop, the palette calls SkiaComponentRegistry.CreateInstance() and adds the component to the DrawingManager.

Palette Integration Options

ApproachEffortFlexibilityUse Case
Auto-discovery via [Addin]MinimalLowSimple plugins with standard metadata
IPaletteProvider implementationMediumMediumCustom icons, ordering, conditional visibility
Custom ComponentPalette subclassHighHighFully custom toolbox UI with search, favorites, recent items

Palette Provider with Conditional Visibility

public class SecurityPaletteProvider : IPaletteProvider
{
    public string CategoryName => "Security";
    public string CategoryIcon => "bi bi-shield-lock";
    public int DisplayOrder => 30;

    public IEnumerable<PaletteItem> GetPaletteItems()
    {
        // Only show security components if user has security license
        if (!LicenseManager.HasFeature("beep.skia.security"))
            yield break;

        yield return new PaletteItem
        {
            DisplayName = "Firewall",
            ComponentType = typeof(FirewallNode),
            IconGlyph = "🛡",
            Tooltip = "Network firewall (stateful or stateless)"
        };

        yield return new PaletteItem
        {
            DisplayName = "IDS/IPS",
            ComponentType = typeof(IntrusionDetectionNode),
            IconGlyph = "🔍",
            Tooltip = "Intrusion Detection / Prevention System"
        };
    }
}

Dynamic Loading from NuGet

Beep.Skia supports loading component families from NuGet packages at runtime without application restart. This enables a plugin marketplace where users can install new diagram families on demand.

NuGet Package Structure

A NuGet package for a Beep.Skia diagram family must include:

Included FilePurpose
lib/net8.0/Beep.Skia.Chart.FamilyName.dllThe compiled assembly with component types
Beep.Skia.Chart.FamilyName.nuspecPackage metadata with Beep.Skia as a dependency
content/BeepAddin.jsonOptional addin manifest for fast scanning without assembly load

Runtime Package Loading

Loading a Component Family from NuGet

public async Task LoadPnIDFamilyAsync()
{
    var nugetManager = new NuggetManager(new NuggetOptions
    {
        Sources = new[] { "https://api.nuget.org/v3/index.json" },
        PackagesDirectory = Path.Combine(
            Environment.GetFolderPath(
                Environment.SpecialFolder.LocalApplicationData),
            "BeepDM", "NuGetPackages")
    });

    // Search for the package
    var searchResults = await nugetManager.SearchPackagesAsync(
        "Beep.Skia.Chart.PnID", take: 10);

    var latestVersion = searchResults
        .OrderByDescending(p => p.Version)
        .First();

    Console.WriteLine($"Found: {latestVersion.Id} v{latestVersion.Version}");

    // Download and extract the package
    var packagePath = await nugetManager.DownloadPackageAsync(
        latestVersion.Id, latestVersion.Version);

    // Load the assembly via AssemblyHandler
    var handler = new AssemblyHandler();
    handler.LoadAssemblyFromPackage(packagePath);

    // Components are now in the registry and palette
    var registry = SkiaComponentRegistry.Instance;
    Console.WriteLine($"PnID components loaded: {registry
        .GetComponentsInCategory("Piping & Instrumentation")
        .Count()}");
}

Addin Manifest (BeepAddin.json)

This manifest allows the palette to display components, their icons, and metadata immediately, deferring the actual assembly load until the user drags a component onto the canvas. This drastically improves startup time when many plugins are installed.

NuGet Package Best Practices

  • Always include both net8.0 and net9.0 TFM targets in your NuGet package.
  • Include a BeepAddin.json manifest for fast scanning without assembly load.
  • Version your packages semantically; the registry validates version compatibility.
  • Use Tags in your .nuspec to categorize packages in NuGet searches.
  • Avoid native dependencies; pure managed assemblies ensure cross-platform compatibility.
