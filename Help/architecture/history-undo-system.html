History / Undo-Redo Architecture

Command-pattern undo/redo system with HistoryManager and DrawingAction subclasses.

The undo/redo system uses a command pattern with HistoryManager and concrete DrawingAction subclasses.

Action Types

  • AddComponentAction: Tracks component creation; undo removes, redo re-adds
  • RemoveComponentAction: Tracks component deletion with full state snapshot
  • DeleteComponentsAction: Removes a multi-selection and its attached lines as one unit
  • MoveComponentsAction: Stores old/new positions for a set of components
  • ConnectComponentsAction: Tracks line creation between connection points
  • DisconnectComponentsAction: Tracks line removal
  • PasteComponentsAction: Re-creates copied components and their internal lines
  • AlignComponentsAction: Records alignment moves across the selection
  • MoveLineAction: Tracks a line being re-routed or re-attached
  • ConnectAutomationNodesAction: Connects automation nodes with port management

Each action implements Execute() and Undo(). The HistoryManager maintains a bounded stack (configurable depth, default 100).

Action Catalog

Every mutating operation is recorded as a DrawingAction subclass. The manager pushes these automatically; hosts only construct them when applying their own commands.
