ETL Professional Features

Lookups, SCD/CDC, aggregation, the expression engine, profiling and run metrics

The ETL family covers the pipeline node types. This page documents the professional-grade capabilities behind them: reference-data lookups (exact and fuzzy), slowly changing dimensions, change data capture, aggregation and reshaping, the expression engine, data profiling and per-node run metrics.

Lookups

ETLLookup — Reference Data Enrichment

Joins the incoming stream against a reference source (table, query or in-memory set) and returns selected columns. It renders as a double-cylinder shape (main data + reference data).

PropertyTypeDescription
CacheModeCacheModeNone, Partial or Full — how much of the reference set is cached in memory.
MatchColumnsstringColumns used as the join key.
ReturnColumnsstringColumns to add to the output row.
FailOnNoMatchboolWhen true, an unmatched row fails the pipeline instead of passing through.
OutputSchemastringDeclared schema of the enriched output, used for downstream validation.

ETLFuzzyLookupNode — Approximate Matching

Matches when keys differ slightly (typos, formatting, transliteration). Similarity is computed with one of four algorithms and gated by a threshold:

PropertyTypeDescription
AlgorithmFuzzyAlgorithmLevenshtein (default), Soundex, Metaphone or JaroWinkler.
ThresholddoubleMinimum similarity in [0, 1]; default 0.8.
MatchColumnstringIncoming column to match.
ReferenceColumnstringReference column to compare against.

Expression Engine

ExpressionEngine evaluates SQL-like expressions over a row dictionary. It is the engine behind derived columns, filters and conditional splits, and it is usable directly:

var engine = new ExpressionEngine();

var row = new Dictionary<string, object>
{
    ["Amount"] = 125.50m,
    ["Country"] = "NL",
    ["Discount"] = 0.15
};

// Scalar result
object total = engine.Evaluate("Amount * (1 - Discount)", row);
Console.WriteLine(total);   // 106.675

// Boolean predicate (for filters and splits)
bool highValue = engine.EvaluateBoolean("Amount > 100 AND Country = 'NL'", row);

Invalid expressions raise ExpressionException with the failing token position, which the host surfaces in the expression tester dialog. See Automation Data Sources for how expressions integrate with datasource-backed nodes.

Pipeline Metrics

Each node run can record NodeRunMetrics, collected in a PipelineMetrics instance for the whole run:

var metrics = new PipelineMetrics();

// Recorded per node by the pipeline runner
metrics.Nodes.Add(new NodeRunMetrics
{
    NodeName = "LookupCustomers",
    RowsIn = 12000,
    RowsOut = 11840,
    Elapsed = TimeSpan.FromMilliseconds(184),
    Status = "Completed"
});

foreach (var node in metrics.Nodes)
    Console.WriteLine($"{node.NodeName}: {node.RowsIn} in / {node.RowsOut} out, " +
                      $"{node.RowsPerSecond:0} rows/s ({node.Status})");

RowsPerSecond is derived from RowsOut and Elapsed. Metrics pair with the workflow engine's run results to give end-to-end throughput reporting; see Workflow Engine.
