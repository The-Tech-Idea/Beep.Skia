State Machine Diagram Family

State machine diagrams with initial, state, and final nodes for modeling system behavior and state transitions.

Overview

Base Control: StateMachineControl : MaterialControl
Namespace: Beep.Skia.StateMachine

The StateMachineControl is the root control for this diagram family. It inherits MaterialControl and provides shared port management, styling, and template methods for all nodes in the family.

This family contains 3 node types.

Node Types

InitialStateNodeFilled circle (black)Initial pseudo-state. Where the state machine begins.

Connection Points

Every node in this family exposes connection points (ports) for linking to other nodes. Port positions are computed lazily by LayoutPorts(), which runs when MarkPortsDirty() flags the layout as stale after a move or resize.

FinalStateNode1+0—

Connection Conventions

When building diagrams with this family, follow these conventions:

  • Initial state has no inputs, one output transition
  • State transitions are labeled with trigger[guard]/action
  • Final state has inputs but no outputs
  • States may contain do/entry/exit activity compartments

Usage Example

Complete example showing creation, node placement, and connection:

C# Example

var sm = new StateMachineControl
{
    X = 50, Y = 50,
    Width = 600, Height = 400
};
drawingManager.AddComponent(sm);

var init = new InitialStateNode { X = 100, Y = 200 };
var idle = new StateNode { X = 250, Y = 200, StateName = "Idle" };
var active = new StateNode { X = 400, Y = 100, StateName = "Active" };
var final = new FinalStateNode { X = 400, Y = 300 };

drawingManager.AddComponent(init);
drawingManager.AddComponent(idle);
drawingManager.AddComponent(active);
drawingManager.AddComponent(final);

drawingManager.ConnectComponents(init.OutPoints[0], idle.InPoints[0]);
drawingManager.ConnectComponents(idle.OutPoints[0], active.InPoints[0]);
drawingManager.ConnectComponents(active.OutPoints[0], final.InPoints[0]);
