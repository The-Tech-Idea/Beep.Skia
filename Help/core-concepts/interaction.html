SelectionManager

SelectionManager (355 lines) handles all selection-state logic for components, connection lines, and connection points. It works in tandem with DrawingManager to provide a cohesive selection experience:

InteractionHelper

InteractionHelper processes raw mouse and keyboard events from the canvas surface and routes them to the appropriate handler based on the current interaction context. It manages a state machine with distinct drag modes:

Drag ModeEnum ValueTriggerBehavior
Component MoveDragMode.ComponentMoveMouse down on a component body, then drag.Repositions the component (and all selected components if part of a multi-select). Snaps to grid if enabled. Fires ComponentMoved on mouse up.
Port ConnectDragMode.PortConnectMouse down on a connection point (port), then drag.Draws a temporary rubber-band line from the port to the cursor. On mouse up over a compatible port, creates a ConnectionLine. Otherwise, cancels.
Marquee SelectDragMode.MarqueeSelectMouse down on empty canvas, then drag.Draws a dashed selection rectangle. On mouse up, selects all components that intersect the rectangle.
Canvas PanDragMode.CanvasPanMouse down with middle button, or Space+drag with left button, then drag.Scrolls the viewport by adjusting PanOffset. The cursor changes to a hand icon.
ResizeDragMode.ResizeMouse down on a resize handle, then drag.Adjusts component Width/Height. Eight handles: N, NE, E, SE, S, SW, W, NW. Snaps to grid if enabled.
NoneDragMode.NoneDefault idle state.Cursor updates based on what is under the mouse (pointer, move, crosshair).

Mouse Event Routing

public void OnMouseDown(SKPoint screenPoint, MouseButton button)
{
    var worldPoint = drawingManager.ScreenToWorld(screenPoint);

    if (button == MouseButton.Middle ||
        (button == MouseButton.Left && IsSpaceHeld))
    {
        _dragMode = DragMode.CanvasPan;
        _dragStart = screenPoint;
        _panStart = drawingManager.PanOffset;
        return;
    }

    var hitResult = HitTestChain(worldPoint);

    switch (hitResult.Type)
    {
        case HitTestType.ConnectionPoint:
            _dragMode = DragMode.PortConnect;
            _connectSource = hitResult.Point;
            break;

        case HitTestType.ResizeHandle:
            _dragMode = DragMode.Resize;
            _resizeHandle = hitResult.Handle;
            _dragStart = worldPoint;
            break;

        case HitTestType.Component:
            _dragMode = DragMode.ComponentMove;
            _dragStart = worldPoint;
            if (!IsCtrlHeld)
                SelectionManager.ClearSelection();
            SelectionManager.Select(hitResult.Component);
            break;

        case HitTestType.ConnectionLine:
            SelectionManager.Select(hitResult.Connection);
            break;

        case HitTestType.None:
            _dragMode = DragMode.MarqueeSelect;
            _marqueeStart = worldPoint;
            SelectionManager.ClearSelection();
            break;
    }
}

Hit-Test Priority Chain

When the user clicks on the canvas, the hit-test chain determines which entity receives the event. The chain is evaluated in strict priority order — the first match wins:

1
Connection Points (Ports)

Highest priority. Each port has a small hit-test radius (typically 8 pixels in screen-space). This ensures users can reliably grab connection ports even on small components.

2
Resize Handles

If the hit misses ports but falls within a resize handle's 6-pixel radius, the resize operation starts. Only active on selected components.

3
Component Bodies

Tests components in reverse Z-order (topmost first). Uses Bounds.Contains(point) for axis-aligned hit testing. Components can override HitTest(SKPoint) for precise path-based hit testing.

4
Connection Lines

Tests against the computed path geometry of each connection line. Uses distance-to-path calculation with a configurable tolerance (default: 6 pixels).

5
Canvas Background

Lowest priority. If nothing else is hit, the canvas background receives the event. Triggers ClearSelection() and starts marquee selection if dragging.

Hit-Test Chain Implementation

private HitTestResult HitTestChain(SKPoint worldPoint)
{
    var portHit = FindConnectionPointAt(worldPoint, PortHitRadius);
    if (portHit != null)
        return HitTestResult.ConnectionPoint(portHit);

    foreach (var comp in GetSelectedComponents())
    {
        var handle = comp.GetResizeHandleAt(worldPoint, ResizeHandleRadius);
        if (handle != ResizeHandle.None)
            return HitTestResult.ResizeHandle(comp, handle);
    }

    for (int i = Components.Count - 1; i >= 0; i--)
    {
        var comp = Components[i];
        if (comp.HitTest(worldPoint))
            return HitTestResult.Component(comp);
    }

    foreach (var conn in Connections)
    {
        if (conn.HitTest(worldPoint, ConnectionHitTolerance))
            return HitTestResult.ConnectionLine(conn);
    }

    return HitTestResult.None;
}

Drag & Drop

Beep.Skia supports two distinct drag-and-drop workflows:

1. Component Palette Drag-Drop

Users drag a component type from the ComponentPalette UI control and drop it onto the canvas. The palette serializes the component type name into the drag data; the canvas deserializes it, instantiates the component via SkiaComponentRegistry, and places it at the drop location:

Palette-to-Canvas Drag-Drop

void OnDragOver(DragEventArgs e)
{
    if (e.Data.GetDataPresent("Beep.ComponentType"))
    {
        e.Effects = DragDropEffects.Copy;
        e.Handled = true;
    }
}

void OnDrop(DragEventArgs e)
{
    var typeName = (string)e.Data.GetData("Beep.ComponentType");
    var worldPoint = drawingManager.ScreenToWorld(
        new SKPoint((float)e.GetPosition(canvas).X,
                    (float)e.GetPosition(canvas).Y));

    var type = SkiaComponentRegistry.ResolveType(typeName);
    var component = (SkiaComponent)Activator.CreateInstance(type);
    component.Initialize();
    component.X = SnapToGrid(worldPoint.X);
    component.Y = SnapToGrid(worldPoint.Y);

    drawingManager.AddComponent(component);
    HistoryManager.Push(new AddComponentAction(component));
}

2. Within-Canvas Repositioning

Drag to reposition existing components uses the DragMode.ComponentMove state machine. During drag, the component position updates in real-time. On mouse up, the final position is committed and a MoveComponentAction is pushed onto the undo stack:

Within-Canvas Component Drag

public void OnMouseMove(SKPoint screenPoint)
{
    if (_dragMode != DragMode.ComponentMove) return;

    var worldPoint = drawingManager.ScreenToWorld(screenPoint);
    var deltaX = worldPoint.X - _dragStart.X;
    var deltaY = worldPoint.Y - _dragStart.Y;

    foreach (var comp in drawingManager.SelectedComponents)
    {
        comp.X += deltaX;
        comp.Y += deltaY;
        comp.MarkPortsDirty();
    }

    _dragStart = worldPoint;
    drawingManager.Invalidate();
}

public void OnMouseUp(SKPoint screenPoint)
{
    if (_dragMode == DragMode.ComponentMove)
    {
        var actions = drawingManager.SelectedComponents
            .Select(c => new MoveComponentAction(c, _originalPositions[c]));
        HistoryManager.Push(new CompositeAction(actions));
    }
    _dragMode = DragMode.None;
}

HistoryManager

HistoryManager implements a command-pattern undo/redo system that records every mutation to the diagram state. Each operation is represented as a DrawingAction subclass with Execute() and Undo() methods:

Action ClassDescriptionUndo Behavior
AddComponentActionRecords a component addition.Removes the component from the canvas and disconnects all its connections.
RemoveComponentActionRecords a component removal with all its connections.Re-adds the component and restores all its connections using saved GUIDs.
MoveComponentActionRecords a component position change.Restores the component to its previous X, Y position. Multiple moves during a single drag are coalesced.
ConnectActionRecords a connection creation between two ports.Disconnects the line and unbinds the ports.
DisconnectActionRecords a connection removal.Re-establishes the connection using the saved port GUIDs.
PropertyChangeActionRecords a change to one or more NodeProperties values.Restores the previous property values and invalidates the component.
ResizeComponentActionRecords a change to Width/Height via resize handles.Restores previous Width and Height values.
CompositeActionGroups multiple actions into a single undoable unit.Undoes all child actions in reverse order. Used for multi-select operations.

Undo/Redo Architecture

The history manager maintains two stacks: an undo stack (past actions) and a redo stack (undone actions that can be re-applied). The redo stack is cleared whenever a new action is pushed, following the standard undo/redo model:

HistoryManager Core Logic

public class HistoryManager
{
    private Stack<DrawingAction> _undoStack = new();
    private Stack<DrawingAction> _redoStack = new();
    private const int MaxHistory = 256;

    public bool CanUndo => _undoStack.Count > 0;
    public bool CanRedo => _redoStack.Count > 0;

    public void Push(DrawingAction action)
    {
        _undoStack.Push(action);
        _redoStack.Clear();

        if (_undoStack.Count > MaxHistory)
        {
            var oldest = new Stack<DrawingAction>(
                _undoStack.Take(MaxHistory));
            _undoStack = oldest;
        }
    }

    public void Undo()
    {
        if (!CanUndo) return;
        var action = _undoStack.Pop();
        action.Undo(drawingManager);
        _redoStack.Push(action);
        drawingManager.Invalidate();
    }

    public void Redo()
    {
        if (!CanRedo) return;
        var action = _redoStack.Pop();
        action.Execute(drawingManager);
        _undoStack.Push(action);
        drawingManager.Invalidate();
    }
}

Tip

The CompositeAction is essential for multi-select operations. When a user drags 5 selected components, all 5 positions are recorded in a single composite action — so one Ctrl+Z moves all 5 back, not just one.
