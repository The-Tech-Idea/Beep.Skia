Overview

SkiaComponent is the abstract base class for every visual element rendered on a Beep.Skia canvas. It provides the foundational infrastructure that all diagram nodes, UI controls, and custom visual components share:

  • Position & Sizing: Absolute X/Y position, Width, Height, and computed bounding boxes in both local and world coordinate spaces.
  • IDisposable: Proper resource cleanup for SkiaSharp objects (paints, surfaces, paths) through the Dispose() pattern.
  • NodeProperties: A configurable parameter dictionary that enables dynamic property editors without requiring reflection. Every component can expose its editable fields as a Dictionary<string, ParameterInfo>.
  • ConnectionPoints: Collections of input and output ports (InPoints / OutPoints) with lazy layout recomputation for performance.
  • DrawContent: A virtual method that subclasses override to render their specific visual content using a SKCanvas.
  • Invalidation: Mark the component or its region as dirty to trigger a redraw on the next render cycle.
  • Hit Testing: Point-inside-bounds and per-feature hit test methods for precise mouse interaction routing.
  • Absolute Coordinate System: All positioning uses an absolute, unscrolled coordinate space. Pan and zoom transforms are applied once globally by RenderingHelper.

The class implements IDrawableComponent and serves as the trunk of a deep inheritance tree spanning 200+ node types across 18 diagram families.

NodeProperties System

Every SkiaComponent exposes its configurable fields as a Dictionary<string, ParameterInfo>. This enables rich, dynamic property editors — such as the in-app property grid — to discover and edit component settings without runtime reflection overhead.

The ParameterInfo class captures:

  • Name & DisplayName: Internal key and human-readable label.
  • Value: The current value (as object).
  • DataType: Underlying CLR type (string, int, float, bool, Color, enum, etc.).
  • Category: Grouping key for property grid sections (e.g., "Appearance", "Layout", "Data").
  • EditorHint: Hints for the UI to choose the right editor widget (combobox, color picker, slider, checkbox).
  • IsReadOnly / IsRequired: Constraint flags.

Subclasses populate the dictionary in their constructor or Initialize() method:

Defining NodeProperties

protected override void Initialize()
{
    base.Initialize();

    NodeProperties["Text"] = new ParameterInfo
    {
        Name = "Text",
        DisplayName = "Label Text",
        Value = "New Node",
        DataType = typeof(string),
        Category = "Content",
        EditorHint = "TextBox"
    };

    NodeProperties["FillColor"] = new ParameterInfo
    {
        Name = "FillColor",
        DisplayName = "Fill Color",
        Value = SKColors.CornflowerBlue,
        DataType = typeof(SKColor),
        Category = "Appearance",
        EditorHint = "ColorPicker"
    };

    NodeProperties["FontSize"] = new ParameterInfo
    {
        Name = "FontSize",
        DisplayName = "Font Size",
        Value = 14f,
        DataType = typeof(float),
        Category = "Typography",
        EditorHint = "Slider:8-48"
    };
}

At runtime, the property grid calls GetProperties() to retrieve the dictionary and SetProperties(dict) to apply changes. The component is then invalidated to reflect the new values on the next draw:

Getting and Setting Properties

var properties = myComponent.GetProperties();

var fontSizeParam = properties["FontSize"];
float currentSize = (float)fontSizeParam.Value;

fontSizeParam.Value = 18f;
myComponent.SetProperties(properties);

myComponent.Invalidate();
canvas.Invalidate();

Note

Changes to NodeProperties values do not automatically trigger Invalidate(). The caller (property editor) is responsible for invalidating the component and canvas after applying changes.

Connection Points

Connection points (ports) are the anchor locations where ConnectionLine segments attach to a component. Each point is an instance of IConnectionPoint stored in either InPoints (input) or OutPoints (output) collections.

Lazy Port Layout

Port positions are recomputed only when the component moves, resizes, or explicitly marks ports as dirty via MarkPortsDirty(). The EnsurePortLayout() method recalculates the screen positions of all ports when needed. This lazy-evaluation approach avoids unnecessary computation during rapid drag operations.

Creating and Layouting Ports

protected override void EnsurePortLayout()
{
    if (!_portsDirty) return;

    InPoints.Clear();
    OutPoints.Clear();

    InPoints.Add(new ConnectionPoint
    {
        Type = PortType.In,
        Position = new SKPoint(X, Y + Height / 2),
        DataType = typeof(string),
        Owner = this
    });

    OutPoints.Add(new ConnectionPoint
    {
        Type = PortType.Out,
        Position = new SKPoint(X + Width, Y + Height / 2),
        DataType = typeof(string),
        Owner = this
    });

    _portsDirty = false;
}

Lifecycle

Every SkiaComponent follows a defined lifecycle from creation through disposal:

PhaseMethodDescription
ConstructionSkiaComponent()Sets default values for X, Y, Width, Height, ZOrder. Initializes empty connection-point collections and the NodeProperties dictionary. Assigns a new Guid.
InitializationInitialize()Virtual method called once after construction. Subclasses populate NodeProperties, create initial ports, set up paints, and define default visual parameters. Call base.Initialize() to ensure ports are marked dirty.
RenderDrawContent(SKCanvas)Abstract/virtual method called every frame. Renders the component's visual representation. The canvas already has pan/zoom transforms applied. Subclasses should use canvas.Save() / canvas.Restore() for local transformations.
InvalidationInvalidate()Marks the component region as needing redraw. Triggers Canvas.Invalidate() on the attached canvas.
Hit TestingHitTest(SKPoint)Returns true if the point falls within the component's bounds. Override for precise per-shape hit testing.
DisposalDispose()Releases all SKPaint, SKPath, SKBitmap, and other unmanaged SkiaSharp resources. Sets disposed flag to prevent use-after-free.

Typical Component Lifecycle Usage

var node = new FlowChartNode("Process Step");
node.Initialize();
node.X = 100;
node.Y = 200;

drawingManager.AddComponent(node);

canvas.Invalidate();

drawingManager.RemoveComponent(node);
node.Dispose();

Tip

When creating a custom component, inherit from the family-level base class rather than SkiaComponent directly. This gives you free Material Design theming, family-specific behavior, and proper palette integration through SkiaComponentRegistry.
